# Логика

MVP сервиса тестов на логику, числа и фигуры. [Публичное демо](https://logika.95.142.45.60.sslip.io/).

9 вопросов → почта и согласие → один бесплатный вывод → подписка 49 ₽ за 7 дней, затем 299 ₽ в месяц → демооплата 0 ₽ → полный разбор и первая тренировка из трёх задач. Демо работает без регистрации, карты и списаний. После девятого вопроса пользователь указывает почту и подтверждает согласие на обработку. Отдельно можно разрешить одно напоминание. В демо отчёт открывается на сайте. Он показывает число верных ответов, игровой IQ-балл, результат по каждой категории и объяснение каждой задачи.

## Запуск

Интерфейс написан на HTML, CSS и JavaScript. Сервер использует Node.js 24+ и встроенный SQLite. Команды выполняются из корня репозитория.

```sh
npm test
npm run build
npm start
```

Локальный адрес — http://127.0.0.1:3000. Данные хранятся в SQLite в `data/logika.sqlite`. Публичное демо работает на VPS под Node.js и сохраняет данные в SQLite. При запуске сервер создаёт базу или применяет обновления схемы из каталога `drizzle/`. Команда `npm test` проверяет API на отдельных базах SQLite. Команда `npm run build` собирает сервер и ресурсы интерфейса в `dist/`. Тот же серверный модуль можно развернуть в Cloudflare Workers с D1.

Сервер считает балл и сохраняет ответы, разбор и статус попытки. Попытку связывает с браузером случайный идентификатор в HttpOnly cookie. Незавершённый тест сохраняется локально в браузере. До оплаты API возвращает один вывод. Демооплата меняет статус один раз. API отчёта проверяет статус при каждом запросе.

## Как оценить изменения UX

Для оценки экрана предложения сравнивайте долю попыток с подтверждённой демооплатой среди тех, где открыли предложение. В таблице `attempts` события отмечены полями `offer_at`, `checkout_at` и `paid_at`. Сравнивайте группы с одинаковым периодом наблюдения и исключайте технические прогоны. Отдельно можно измерить, сколько посетителей дошли от сохранения почты (`consent_at`) до предложения. Эти показатели описывают поведение в демо.

## Развёртывание в своём аккаунте Cloudflare

Для публикации по адресу на workers.dev выполните следующие команды из корня проекта.

1. Войдите в Cloudflare через `npx wrangler login`.
2. Создайте базу: `npx wrangler d1 create logika-iq-demo`.
3. Скопируйте `wrangler.toml.example` в `wrangler.toml` и внесите UUID созданной базы.
4. Выполните `npm run build`, затем `npx wrangler d1 migrations apply logika-iq-demo --remote` и `npx wrangler deploy`.
5. Откройте выданный URL и пройдите тест до отчёта, чтобы проверить Worker и запись в D1.

## Развёртывание на российском VPS

На Linux с Docker Engine и Compose создайте `.env` в корне проекта с `PUBLIC_ORIGIN=https://demo.example.ru`. Направьте DNS домена на публичный IP сервера и откройте входящие TCP 80 и 443. Выполните `docker compose up -d --build`. Caddy принимает публичные запросы, а приложение доступно внутри сети Compose. SQLite хранится в томе `attempts`, который сохраняется при пересборке контейнера.

Для проверки по IP до настройки DNS можно задать `PUBLIC_ORIGIN=http://ПУБЛИЧНЫЙ_IP`. В таком режиме браузер использует HTTP. Для ссылки работодателю используйте HTTPS.

## Кабинет администратора

Откройте личную ссылку вида `https://ваш-домен/admin#ключ`, затем введите логин `admin` и пароль `admin`. Ссылка служит секретом доступа. Сервер принимает пару только вместе с действительным ключом, затем устанавливает защищённую cookie на 8 часов. Повторные прохождения группируются по почте. Для смены ссылки и отзыва действующих сессий замените серверный секрет `ADMIN_AUTH_SHA256` (64 случайных шестнадцатеричных символа) и перезапустите сервис. Ключ ссылки равен HMAC-SHA256 в hex от строки `login-link:v1` с серверным секретом в UTF-8. Храните секрет и ссылку вне репозитория.

Раздел «Обзор» считает старые завершения из attempts, а переходы по экранам — для новых прохождений, связанных с journeys. Воронка считает попытки по самому дальнему достигнутому этапу. В «Прохождениях» видны этап и номер вопроса, в «Пользователях» адреса сгруппированы.

Раздел «Рассылка» готовит однократное напоминание. Он исключает адреса с любой демооплатой, без отдельного согласия и уже обработанные адреса. Доступна выгрузка черновика EML со скрытой копией до 50 адресов. Подготовленный черновик учитывается отдельно от принятых SMTP писем.

Для прямой отправки на VPS задайте MAIL_FROM и SMTP_CONFIG в окружении сервиса. SMTP_CONFIG — абсолютный путь к доступному сервису закрытому файлу конфигурации curl с параметрами url (smtp/smtps) и user (логин и пароль). Перезапустите сервис. После явного подтверждения администратором сервер создаёт очередь в SQLite, сверяет согласие и оплату перед отправкой каждого письма и сохраняет результат передачи. Неопределённые результаты требуют ручной проверки у провайдера. Для Workers доступна выгрузка EML.

На VPS при входе открывается недельный демопример с 240 вымышленными прохождениями за 12–18 ноября 2026. Он создаётся в отдельной базе SQLite в памяти. Переключатель «Реальные данные» открывает рабочую статистику. В демопримере рассылка ограничена проверкой аудитории, и её можно повторять без настройки почты.

Управление демоподпиской открывается из отчёта и подвала. Первый путь отмены включает десять экранов без нумерации. По порядку предлагаются месяц за 149 ₽, пауза на 30 дней, персональные задачи, месяц за 99 ₽, приглашение для близкого, задача дня, повторный тест через неделю и семь дополнительных дней. Завершают путь три задачи повышенной сложности и четырнадцать дней в подарок. На каждом экране две кнопки: принять предложение или продолжить отмену. Последний отказ отключает продление. Скидка действует на одно продление. При повторном входе в отмену после принятия предложения начинается новый путь из десяти экранов. Уже пройденные экраны незавершённой попытки сохраняются. Каждая льгота предоставляется один раз. Раздел «Отмены» показывает принятые предложения, текущий экран незавершённого обращения, подтверждение отмены и историю выбора. Старые обращения сохраняют свою историю. Личная ссылка открывает управление подпиской и оплаченный разбор.
